### 用户场景与测试

#### 用户故事 1：下载、安装并使用统计报告（P1）

作者从正式版本入口取得源码/框架；普通用户取得独立 skill 或生成 suite，按 README 操作。优先级来自当前稳定资产缺少报告命令。独立测试使用新解包目录和合成文件，不调用模型。

**验收场景**：

1. **AC-1**：给定两个已有公开仓库，当发布 v0.2.0，则源码/tag指向同一获验证和评审的准确提交，GitHub Release 提供五件套，Gitee 提供对应 tag/source 与固定同版下载入口；下载后摘要匹配。保留 v0.1.0。
2. **AC-2**：给定全新解包及 Python 3.11+，当按 BASIC 使用路径安装至隔离 WorkBuddy 项目并实际运行普通脚本，则输出符合示例输入；登记为 basic、observation disabled，不新增采集 hooks、receipt要求或统计记录。作者与消费者入口说明清楚。
3. **AC-3**：给定同版新解包框架及显式选择的支持来源，当按 README US-003B 生成报告，则确有单一离线 HTML 和预期的合成统计/来源诊断。基础安装没有观测数据时按现有规则说明，不能伪造生产成功率。完整呈现和异常行为仍由 REQ-004 验收定义，本次不重定口径。
4. **AC-4**：给定 v0.1.0 的隔离 BASIC 安装，当显式选择 v0.2.0 框架升级，则框架版本更新，原业务内容、业务版本及已保存安装模式保留；实际脚本输出继续正确。省略模式、忙状态、局部修改及恢复行为沿用现有更新契约。
5. **AC-5**：给定 v0.2.0 的 README、作者说明和 Release notes，当核对版本及支持范围，则包含报告入口、安装/升级路径、固定资产来源和实验边界，版本标识与制品一致；不声称真实模型、桌面、自动统计或 T011 已完成。
