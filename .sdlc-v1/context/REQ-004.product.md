### 决定

#### DEC-401：沿用任务/调用、首次/最终与三项比例

- **状态**：confirmed
- **决定**：独立呈现 `tasks.one_shot`、`tasks.final`、`calls.one_shot`、`calls.final` 四个组合。每组显示 N/S/K/U、下限成功率 S/N、已知结果成功率 S/K、结果覆盖率 K/N，不将不同分母或首次/最终混合成一个成功率。
- **规则**：N 为选定范围内全部样本，S 为 pass 数，K 为 pass 或 fail 数，U 为其余结果数；满足 `0 ≤ S ≤ K ≤ N`、`N = K + U`。分母为零的比例显示“无样本”，并说明是总样本还是已知结果样本不足，不显示 0% 或 100%。unknown 保留在 N 中。结果覆盖率不等于观测完整度，不据此计算捕获率或判断没有介入。
- **来源**：REQ-002/DEC-205；[README.md](../../README.md) 的 US-003；`src/selc/records.py` 的 `_metrics` 与 `stats`（核对基线 `1dd8ad028f0d4efc40c5aaa5530d2dbda090ef38`）。

#### DEC-402：跨项目先并列查看

- **状态**：confirmed（主 Agent 在既有授权内接受的普通默认）
- **决定**：多项目总览每个项目独立显示状态、统计范围和四轴指标；用户可切换到一个项目查看分组。跨库可能含同源或重复导入样本，因此本次不把项目分母相加，也不显示跨项目“总成功率”。同一个规范化来源重复选择只展示一次。
- **原因**：已有库内导入去重不证明多个库彼此独立。并列视图可直接交付比较价值，无需新增跨库身份合并语义。
- **来源**：主 Agent 在本轮 spec brief 明确接受此默认；现有 `records._deduplicated_samples` 只处理当前数据库。不把它写成用户确认过跨库去重算法。

#### DEC-403：范围先于数值

- **状态**：confirmed（主 Agent 在既有授权内接受的普通默认）
- **决定**：提供项目、suite、suite version、harness 筛选；默认排除测试，提供明确的“包含测试样本”开关及当前状态。HTML 内的筛选与开关仅使用生成时已纳入的最少统计数据，不重新读取源数据库。筛选作用于该轴对应的样本范围，指标和分组同步更新；缺失维度作为 unknown 可见，不静默丢弃。每个项目生成时使用一致读取快照，并显示读取/生成时间、已纳入范围和来源状态；多项目读取时逐项显示各自时点，不暗示跨库原子快照。
- **原因**：用户必须知道当前数字来自哪里、包含哪些数据以及是否新鲜，才可比较结果。
- **来源**：主 Agent 在本轮 spec brief 明确接受此默认；README/US-003 与现有 `stats` 的 `includes_test`、`generated_at`、groups。现有函数尚未提供这些筛选参数，不能把该决定写成已有能力。

#### DEC-404：以桌面统计工作台组织信息

- **状态**：confirmed（受委托的普通布局实现默认，未经用户视觉确认）

### 用户场景与测试 *(必填)*

下列场景构成独立 HTML 报告的验收范围；统计合约沿用现行来源，交付形态和普通实现默认按 DEC-402–405 生效。

#### 用户故事 1 - 理解一个项目的统计（优先级：P1）

使用者打开已指定项目，确认统计范围并查看任务/调用的首次与最终结果，避免把 unknown 或缺数据读成成功。

**为何此优先级**：正确理解既有统计是新增界面的最小价值。

**独立测试**：用本地可控数据展示四轴数值与空态，不需要模型或真实业务执行。

**验收场景**：

1. **SCN-401**：给定同一项目的任务最终轴有 4 个样本（2 pass、1 fail、1 unknown），当查看该轴，则显示 N=4、S=2、K=3、U=1、S/N=50%、S/K≈66.7%、K/N=75%；其他三轴各按自身结果显示，调用数量不会成为任务分母。
2. **SCN-402**：给定某轴 N=0，当查看该轴，则三个比例均为“无样本”；给定 N=3、K=0、U=3，则 S/N 与 K/N 为 0%，S/K 为“无已知结果样本”，不能写成已知成功率 0% 或 100%。
3. **SCN-403**：给定 basic 项目且只有普通执行、没有统计记录，当打开，则明确“basic 默认不采集/当前无统计样本”，不能显示运行失败或成功。只凭缺库无法核实模式时显示“缺少统计数据库，采集状态未知”，不能猜成 basic。
4. **SCN-404**：给定存在保留的历史样本且有可核实的采集不可用状态，当打开，则历史数值仍可见并标明其时点，采集不可用单独提示；不能把历史数据称为实时完整观测。没有可核实状态时写“采集状态未核实”，不从数字推断健康。

#### 用户故事 2 - 筛选并比较显式选择的项目（优先级：P1）

维护者在一个入口并列查看所选项目，再选一个项目按 suite、版本和 harness 查看同范围指标与分组。

**为何此优先级**：满足多项目查看需求，同时保持来源和分母可解释。

**独立测试**：两个本地项目包含重叠导入、不同版本与测试样本；用户可在总览和单项目之间切换。

**验收场景**：

1. **SCN-405**：给定只显式选择 A、B，其中 B 含 A 已导出的样本，当打开总览，则只展示 A、B 并列结果与各自时点，不扫描第三个项目，不显示两个 N 相加的全局成功率；重复指定同一来源不增加总览行。
2. **SCN-406**：给定项目含不同 suite/version/harness、测试与非测试样本，当首次打开，则默认排测试；选择任一筛选或包含测试后，四轴和分组都使用对应样本范围，当前筛选可见；重置恢复默认。筛选为零结果时说明“当前筛选无样本”，提供重置操作，不报源库故障。
3. **SCN-407**：给定旧样本部分维度缺失，当选择 unknown 分组，则这些样本可见并仍按原有规则计入分母；改变筛选不能将缺字段样本默认为当前版本。
4. **SCN-408**：给定多个项目中一个无法读取，当查看总览，则该项目单独报错，其余成功项目保持可查看；不能静默省略失败项目或将其记为 N=0。

#### 用户故事 3 - 识别快照、错误并恢复查看（优先级：P1）

用户知道当前数字何时产生、包含什么范围；读取失败时获得恢复动作，不损害来源数据。

**为何此优先级**：只读与快照可信度是查看工具的必要条件。

**独立测试**：以缺失、拒绝访问、非法/不支持格式、暂时忙和读取中有写入的本地数据执行相应旅程。

**验收场景**：

1. **SCN-409**：给定来源不存在、目录错误、无读取权限、数据库损坏或版本不支持，当读取，则分别显示可理解的原因与选择其他来源/修正访问/使用兼容版本等动作；不自动建目录、建库、迁移或修复，也不执行源数据中的指令。
2. **SCN-410**：给定读取期间有合法后台写入，当完成一次读取，则同一项目的四轴和分组来自同一一致快照；新数据只能出现在下一次成功读取。页面标明读取/生成时点、筛选范围；多项目分别标时点，不承诺跨库同一事务。
3. **SCN-411**：给定生成时来源暂时忙或用户重复请求生成，当操作结束，则不产生重复项目行或多次计数，错误信息说明可以修正后重新生成；失败不损坏已有有效报告。打开报告后重复切换项目和筛选，指标与当前选择一致，旧项目结果不会覆盖新选择。
4. **SCN-412**：给定只有键盘与窄屏，当切换项目、筛选、重置并阅读指标说明，则操作可达、焦点可见、标题和表头关系明确，状态不依赖颜色，整页不因宽表产生无边界横向滚动。
5. **SCN-413B**：给定已生成报告且源库后来变化，当重新打开或刷新旧 HTML，则仍显示原快照与时点；只有重新生成的成功报告显示新数据，页面没有声称读取实时数据库的刷新动作。给定重新生成整体失败，则已有有效报告保持原内容与原生成时间，失败输出不会冒充新报告成功。

#### 边界情况

- 未选择项目、有效空库、basic 无记录、当前筛选无样本、全部结果 unknown、采集状态未知/不可用分别有准确说明，不共享笼统的“没有数据”。
- 本地旧数据与已导入数据沿用现有去重及冲突变 unknown 的规则，不由 UI 重新判 pass/fail。去重、导入修订与统计语义的权威仍是现有 records 合约。
- 长项目名、长 suite/version、unknown 维度仍可识别；显示文本按数据处理，不作为 HTML 或脚本执行。
- 部分项目失败、状态信息缺失、读取超时/忙时，不隐藏来源范围，也不把不可读取当零样本。

### 成功标准 *(必填)*

#### 可衡量结果

- **SC-401**：离线确定性样例覆盖 SCN-401–411，四轴 N/S/K/U 与现行统计口径一致，所有零分母比例不显示假百分比，默认报告不混入测试。
- **SC-402**：在无其他写入者的隔离检查中，生成/重新生成前后源数据库内容与 schema 保持不变，无新源目录、无生产事件重放、无模型请求；并发场景另核实生成读取不产生写入。HTML 打开、筛选、切换和浏览器刷新不访问源数据库或外网，交付物不含 CON-402 排除的数据。
- **SC-403**：在真实 HTML 完成“并列比较 → 选择项目 → 按版本/harness 筛选 → 重置”，能看到相应范围与时点；键盘、375/768/1440px 宽度及 AA 对比检查通过，无不可读数值或无法使用的操作。定性走查不当作成功率统计。
- **SC-404**：完成 SCN-413B，并证明整体生成失败不覆盖已有有效报告，旧文件时点不被更新冒充成功。T011 和 observed 未验收范围仍按事实显示，不因以上检查通过而改状态。

质量验收沿用上面的结果与场景：源数据安全、一致读取、错误恢复、无外网依赖、信息可达均需真实证据。生产规模/耗时基线尚无事实，不承诺虚构的吞吐量或实时性；Plan 应用有界本地 fixture 报告实际项目数、样本量和读取耗时，并限制忙/超时等待，失败可恢复。

### 范围外

沿用 OUT-401；本次不提供跨项目全局成功率、趋势预测、自动建议、样本编辑、云端同步、实时网页服务或可公开分享的部署。交付形态为 DEC-405 的独立 HTML 报告。

### 假设

- 使用者以本机桌面查看为主；窄屏可读与可操作，不引入手机原生客户端。
- 原有统计指标足以支撑首版查看；界面不需要读取 prompt/原生日志即可解释分母与当前范围。
- 生产规模和首次生成耗时尚无基线；通过 Plan 的有界 fixture 建立事实，不影响已确认的静态报告旅程。

### 依赖

- 复用现有 SQLite 与 records 指标/去重语义。当前 `open_database` 会建目录、写入 schema，`export_snapshot` 会更新导出修订；均不能直接充当只读查看入口。Plan 必须明确真正只读 reader、受支持 schema、筛选复用和单库一致读取，以及对正在写入的源库的失败/重试行为。
- 当前 `stats` 已提供四轴、分组、`metric_contract.version=1`、`includes_test` 和 `generated_at`；新项目/suite/version/harness 筛选与只读来源状态仍待实现。不得声称现有 stats 已具备所有拟议 UI 能力。
- 本 Requirement 的查看实现不依赖 T011 真实评估完成；展示实验事实不变，不能反过来为 T011 出具成功证据。
- 原型选择沿用确认日志中的包内适配例外：现行统计合约、明确场景与用户静态报告旅程足以指导普通实现，本次不另建模拟原型。首份真实生成 HTML 是 Build 最早增量，检查筛选、数据范围与一次失败恢复；它不是原型确认或正式 Validate 证据。当前阶段不创建 HTML/生产代码或第二份 PRODUCT/DESIGN。
- design 方法沿用主 Agent 本次已核对的 Impeccable 能力（context 实际 exit 0、无现有 UI/自动 design hook）；本子任务未运行 launcher、未下载引擎，也未取得任何渲染/可访问性通过证据。

## 发布后观察计划（SDLC 补充）

- **观察条目**：用户能否正确指出项目/测试/版本范围、分母、unknown 与快照时点，能否通过一次失败后的恢复动作继续查看；是否发生误读、源库变更或数据外发。
- **基线或未知原因**：无现有统计 UI、完成时间或误读率基线；目前只有现行 CLI/records 合约，不能编造改善百分比。
- **目标或判断方式**：交付前先用上述离线样例与真实 UI 走查建立基线；本机首次实际使用时人工核对四轴与独立预期，并记录失败/unknown/未验证项。源数据变更、隐私越界或把缺数据读成成功均需修正。
- **观察窗口**：本地交付后首次真实查看与一次后续数据更新/重新生成；长期天数和样本量尚未承诺，本轮不创建定时任务或后台监控。
- **负责人**：主 Agent 负责交付验收与收集本轮用户反馈；长期维护负责人未指定，不伪造值班安排。
- **反馈回流**：交付前反馈更新本文受影响场景；已发布后的新范围进入新的 Requirement，原资格/采集问题仍回流原对应需求。
- **确认来源/关联决定**：NEED-401、CON-401–403、DEC-405；沿用本轮本地验收与反馈范围，不承诺额外模型运行或长期监控。
