# F-002 / T011 native request packet implementation evidence

Date: 2026-10-28. Tested source revision: `f4497bce82256a49ad7e5aa1cb33491a52d0034e` plus this uncommitted implementation. `allowed_transitions: []`; T011 remains in progress.

The runtime now recognizes mutually exclusive `managed action --request <file>` and `--request-source native` forms. For the native form, only the trusted current Codex `PreToolUse` collector revalidates P0 and the persisted first supported P1 prompt proof, extracts the structured DTO, and writes a short-lived receipt/event/subject/installation-bound packet below the project `.selc/` directory. Later same-turn records may contain the observed command completion, `Reasoning`, custom-tool-output, and token telemetry serializers, but cannot add a user message, another turn, a fork, compaction, or an identity conflict. Those suffix records never supply DTO text or authorization. The native event retains only packet `version` and `digest`; it does not retain a native transcript path or the DTO. The consumer requires a no-follow regular file, canonical bytes, full digest, receipt, subject, installation, request, and expiry match, and deletes the packet after it is used. Packet creation is no-clobber, linked from a fully fsynced private temporary file whose fixed name derives from the receipt. Recovery validates existing durable event metadata and never promotes packet sidecar claims into the database. Current consumption and exact-request Stop cleanup derive their packet pair from the receipt DB without enumerating the packet directory. A suite admits at most 64 ready native packets, including expired receipts awaiting cleanup. Before another action Pre reserves a packet, the runtime directly cleans and terminalizes a bounded set of expired receipt-owned pairs; exact-request Stop includes expired ready pairs and terminalizes a receipt only once both deterministic paths are absent. The separate 64-entry directory batch remains best-effort expired/orphan cleanup only.

The same source change keeps the bounded Codex routing discovery read: one exact `/bin/cat <current installer-owned routing SKILL.md>` with immutable registration and entry-byte checks, protected reader device/inode/byte identity, P0/P1/Pre/Post/Stop reconciliation, and no receipt/task/call. Unsupported compound reads remain unmanaged and retain `unknown_change`. A replay of an old exact-cat unmanaged raw row uses its original digest family and leaves old applied/pending classification and sticky unknown facts unchanged.
