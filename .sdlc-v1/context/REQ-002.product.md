### 决定

#### DEC-201：统一受管入口、复用 SQLite 与既有记录

- **状态**：confirmed（产品原则与 SQLite 选择）；工程协议由 Plan 决定。
- **决定**：正常业务调用自动经过可验证的受管执行路径，宿主事件和业务执行证据进入本机 SQLite，并形成既有 task / invocation / delivery / feedback 记录。安装携带必要 adapter / runtime / 自检，不要求使用者或业务 Agent 逐次执行记录 CLI，也不能只在 SKILL.md 提醒“记得记录”。
- **约束**：说明读取、扫描、Skill 工具成功与业务实际执行分别识别；纯指令 skill 也不能靠人工登记补齐。显式和自动调用保留实际 skill / suite 版本、执行方 / 发起方；来源或任务关联不足保留 unknown。不同宿主、会话、子 Agent 可关联同一业务目标，但不凭相似文字强行合并。
- **完整性**：受支持路径的启动和已产生结果耐久保留；重复 / 乱序 / 重放 / 崩溃恢复不丢失、不重复计数。无法恢复的区间标明 gap，不能声称完整。SQLite 表结构、可靠关联、消费位置和恢复控制不在本 Spec 预定。
- **用户证据**：SRC-204、SRC-206；实际调用与归属语义继承 SRC-202。

#### DEC-202：完整时间线与保守分类

- **状态**：confirmed
- **决定**：默认使用结构化事件与保守规则；难判的参与者、任务归属、介入类型、反馈含义或首次交付保留 unknown，并保留判断依据。默认不启动语义分类 LLM / LLM judge；将来引入需有明确授权与独立评估，不能据模型预算默认为已选。
- **双轴**：从原始业务请求保留完整任务时间线，one-shot 从预先声明的必要客观输入就绪后判定。必要输入准备与纯权限点击单列，不算业务介入；业务判断、纠错、补做和流程必需的业务审核即使在开头也算介入；内部自动检查 / 重试允许。交付后的自愿反馈不追溯算执行介入。
- **首次交付**：第一次向用户交付、绑定原需求的业务产物与内部草稿 / 检查区分。首次明确失败后补救成功只更新最终轴，不能恢复首次成功；`Stop`、进程退出 0 或 Agent 自报完成均不能证明成功。新增要求不自动倒判原交付；迟到原要求负反馈可修订对应交付，保留历史。
- **参与者与外部变更**：只按可信来源区分真人、宿主自动续跑、Agent 与权限事件；不因事件名含 User 就算人工。无法归属的文件变化、并发任务归属或缺失时间段使相关判断 unknown，不能把“没观测到介入”视为“无介入”。
- **用户证据**：SRC-207 确认分类默认；其余是 SRC-202 / DEC-005 至 DEC-008 的现有规则在自动接入中的落实，不表示已选定具体分类算法。

#### DEC-203：可扩展、独立的业务产物验证

- **状态**：confirmed（交付能力和结果语义）；具体接口、信任与运行限制由 Plan 决定。
- **决定**：维护者可为新套件声明执行前已确定的必需检查；扩展至少覆盖一个不依赖内置固定 renderer 的简单文本 / 报告路径。检查绑定输入、产物版本、规则 / checker 版本及逐项依据；产物变更使旧结果不再适用于新版本，必须重新检查。
- **结论**：全部必需项通过为 pass；明确必需项失败为 fail；没有已知失败但缺检查、超时、不可用或证据不足为 unknown。skill 本体结构检查与业务产物验证分开。自动结果和用户反馈分别保留；好评不能抹去已证实失败，冲突核对同一版本和验收项后处理。
- **评估独立性**：优先确定性 checker；baseline / candidate 的业务输出必须由真实 harness 分别执行对应 skill 正文产生，再由候选不可改写的独立规则和固定回归 / 保留集评分。不得以固定 renderer 同时生成 expected 与输出、自改 oracle 或 SKILL.md 结构通过证明指令效果改善。
- **用户证据**：SRC-206 第 4、5 项；SRC-202 / DEC-007、DEC-011；默认分类遵守 SRC-207，预算以SRC-210更新为准。JSON schema、版本协商、隔离 / 超时具体值不冒充用户已确认方案。

#### DEC-204：采集不可用时暂停，修复后可对账恢复

- **状态**：confirmed
- **决定**：采集未启用、必要宿主能力不支持或本机持久写入失败时，暂停受管 skill 并给出可恢复提示。启动失败时不开始业务；执行中失败时停止新增无法留证的业务动作，保全已发生动作及产物证据，修复 / 回放后才能恢复。不宣称能撤销已发生的外部副作用，也不能静默绕过继续并记成成功。
- **已拒绝替代项**：采集不可用默认直接继续，只记 unknown。
- **恢复原则**：恢复不重做已证实完成的业务动作，不用重新建任务抹去中断；无法确认完成的动作保留 unknown / gap。故障识别、在途动作界限和幂等协议由 Plan 明确。
- **用户证据**：SRC-203、SRC-204、SRC-206 第 2 项；故障行为是“暂停并提示修复”在启动 / 运行中 / 恢复场景的可观察验收展开。

#### DEC-205：统计口径与兼容保持

- **状态**：confirmed
- **决定**：业务 task 和实际 invocation 独立计数；同一目标跨阶段、重试、恢复不重复增加 task，实际重新激活 skill 仍计独立调用。首次 one-shot 与最终交付各自保留成功 / 未达成 / unknown，运行中 / 取消 / 中断不从已观测分母删除。分别展示样本数、时点、版本、harness、成功率下界、已知结果成功率与结果覆盖率；观测完整度 / gap 与结果覆盖率分开。
- **公式**：每轴独立满足 `0 ≤ S ≤ K ≤ N`、`N = K + U`；下界为 `S/N`，已知成功率为 `S/K`，覆盖率为 `K/N`。task 按发起方、invocation 按执行方分组。对应分母为零显示“暂无样本”，不显示虚假百分比。
- **数据兼容**：已有本机记录与显式导出 / 导入的身份、双轴、unknown 和修订语义保持；旧数据没有新采集证据时不能补成完整 / one-shot 成功。重复导入、事件回放及反馈修订不重复计数；无法支持的版本清楚报错并保护既有数据。具体迁移和导出版本策略由 Plan 选择。
- **数据边界**：默认本机保存；显式最少统计汇总不带业务 / 反馈正文；明细不自动过期，按套件 / 时间删除并说明影响，不自动追回已分享文件。
- **用户证据**：SRC-202 / DEC-004 至 DEC-008、DEC-017；SRC-206 第 2、3 项未改变这些现有行为。

#### DEC-206：真实迭代、贡献、发布与升级分开验收

### 用户场景与测试 *(必填)*

场景描述必需行为；一个场景不等于必须消耗一次模型请求。重复、迁移、故障和分类边界可在本地独立 fixture 检查；正常发现 / 自动选择、各端双轴结果与真实评估 / GitHub 闭环必须使用相应真实入口证据。真实请求遵守CON-205的最新整体授权、串行和单次时限，不为凑场景重复无新证据的失败。

#### 用户故事 1 - 正常发现、显式或自动调用（优先级：P1）

安装使用者从套件链接完成当前项目 / 当前宿主的完整安装后，可以像普通 skill 一样发现和调用；Agent 也可根据业务请求自动选择，统计无需额外操作。

**为何此优先级**：没有正常使用入口，探针和记录 API 不能满足 NEED-201。

**独立测试**：分别在实际 Codex 桌面和 WorkBuddy 安装简单套件；保留安装结果、宿主版本 / 入口、实际激活 / 业务动作原件及独立预期。自动选择案例只提供业务目标，不在请求中点名 skill 或粘贴文件路径。扫描负例另行核对。

**验收场景**：

1. **SCN-201**：**给定** 两端分别完成项目级安装与必要宿主信任，**当** 使用正常发现 / 显式调用入口，**则** 可发现各独立 skill、运行正确版本、自动出现 task / invocation 及执行方 / 发起方依据；不要求手动运行登记 CLI。安装结果显示位置、版本、可调用入口和维护入口。
2. **SCN-202**：**给定** 已安装且当前宿主索引已更新，**当** 只描述匹配业务目标，**则** 宿主实际选择并执行对应 skill，自动记录真实调用；保存选择与执行依据。不能用事先硬编码直接执行受管命令冒充自动选择。
3. **SCN-203**：**给定** 只读 / 搜索 / 索引 SKILL.md，**当** 没有实际业务激活，**则** invocation 不增加。若只有说明加载证据则不能报告已调用，更不能推导业务成功。
4. **SCN-204**：**给定** 同源同版本已装，或存在名称 / 本地修改冲突，**当** 再安装，**则** 前者复用，后者停止覆盖并解释冲突；缺必要信任 / 不受支持版本时显示修复步骤，不谎报可用。

#### 用户故事 2 - 自动记录耐久、故障可恢复（优先级：P1）

使用者完成正常业务后，可直接查询本机统计。受管执行会发现采集缺失并暂停，重放和恢复不增加重复样本，也不丢掉已开始任务。

**为何此优先级**：保证分母可信，并把探针接入正式记录能力。

**独立测试**：从宿主 adapter 入口与受管执行路径取证，和独立宿主轨迹 / 预置动作清单对账；不能直接调用 records API 生成“应捕获数”。本地注入写失败、崩溃、重复 / 乱序和版本兼容样例，真实停用采集案例从宿主实际执行。

**验收场景**：

1. **SCN-205**：**给定** 正常受管执行已启动，**当** 查询统计与时间线，**则** 宿主观测自动进入同一正式记录系统；每个已观测 task、实际 invocation、delivery 及版本可追溯，不要求用户补录。测试 / 评估样本与真实业务分类分开。
2. **SCN-206**：**给定** 相同事件重复到达、完成早于开始到达或消费进程中断，**当** 修复后重放 / 对账，**则** 仍得到同一业务事实及唯一计数；不同实际调用不被误去重，同一目标不会因恢复新建 task。无法恢复的缺口显示 gap。
3. **SCN-207**：**给定** hooks 未启用、必要证据缺失、写库失败或版本不支持，**当** 即将开始业务，**则** 受管执行在业务动作 / 产物写入前暂停，提示原因和修复方式；不能继续并声称采集完整。未启动的预检暂停不增加已启动业务 task / invocation 分母，其诊断另行保留，不能冒充“业务执行后 unknown”案例。
4. **SCN-208**：**给定** 业务已开始后采集失效或宿主崩溃，**当** 恢复，**则** 已启动样本和已发生动作的依据保留，新增无法留证的动作停止；修复后对账不重复业务副作用。证据不足的结局保持 unknown，不把整体 Agent 退出 0 当业务完成。
5. **SCN-209**：**给定** 现有 SQLite 记录和旧版汇总导出，**当** 接入新采集并升级 / 导入，**则** 已有身份、双轴、unknown 和反馈历史保持；重复导入不重复统计，旧数据未拥有的新证据不伪造。无法支持的版本拒绝处理并保护现有数据，失败迁移不能留下误称成功的半套记录。

#### 用户故事 3 - 解释 one-shot、纠错与 unknown（优先级：P1）

作者能查看原始请求到交付 / 修订的完整时间线，理解首次与最终结果的差异，看到分类依据及未知原因。

**为何此优先级**：仅能计数或双端全 unknown 不等于自动统计完成。

**独立测试**：每端真实产生正常 one-shot pass、原要求纠错后首次未达成 / 最终 pass、观测不足 unknown；必要输入、纯权限、自动 retry、模糊 / 迟到反馈及并发归属用独立标注样例验证。报告每类正确、错误、unknown 数，不编造自然语言准确率或以全 unknown 通过。

**验收场景**：

1. **SCN-210**：**给定** 必要输入就绪、原要求固定、观测充分且无业务介入，**当** 首次面向用户的产物通过全部必需检查，**则** 首次和最终均成功，保留“未用户确认”等反馈状态；自动检查 / retry 记录在时间线但不算人工介入。
2. **SCN-211**：**给定** 首次产物有明确必需项失败，**当** 用户纠错原要求后补救产物通过，**则** first fail / final pass，保留纠错、原失败与新产物版本，不恢复首次成功、不通过新建 task 隐藏介入。
3. **SCN-212**：**给定** 前置缺预先声明的客观输入，或只需纯工具权限点击，**当** 用户提供输入 / 权限，**则** 单列事件和等待，不算业务介入；同条消息若要求方案选择 / 业务口径判断则按业务介入，无法分清则 unknown。
4. **SCN-213**：**给定** 宿主自动续跑、Agent 消息、直接文件变更或并发业务目标，**当** 解释 actor 与归属，**则** 不按 UserPromptSubmit 名称猜真人，不把无归属变更归给所有 task；来源或完整性不足的相关轴为 unknown，并显示依据 / 缺口。
5. **SCN-214**：**给定** 已交付版本收到迟到原要求负反馈、新要求或好评与 checker 冲突，**当** 重算，**则** 原要求负反馈可修订该交付并保留历史，新要求不倒判原交付；已证实必需项失败不能被好评覆盖，模糊 / 无法核对的相关结论 unknown。自愿反馈不追溯算执行介入，流程必需审核算介入。
6. **SCN-215**：**给定** 一个目标跨多阶段 / 子 Agent / 宿主 / 自动恢复，或存在两个独立目标，**当** 汇总，**则** 前者一个 task、各次真实调用独立计数，后者两个 task；关联不明不强行合并。首次与最终独立计算 N / S / K / U、下界 / 已知成功率 / 覆盖率，分母为零显示暂无样本。
7. **SCN-216**：**给定** 运行中、取消、中断或只有 Agent 自报完成，**当** 生成报表，**则** 保留已观测分母和状态；缺结论不补 pass。观测完整度与结果覆盖率分别展示，无法取得独立应记录基数时捕获率 unknown。

#### 用户故事 4 - 扩展业务验证器并保护证据（优先级：P1）

维护者为新业务套件配置独立 checker，能够自动识别正确、错误与证据不足的产物，而不修改 SELC 内置固定 renderer。

**为何此优先级**：有调用证据仍不足以判断业务结果。

**独立测试**：用至少一个非内置渲染路径及固定独立预期覆盖正确、错误、缺检查、checker 异常 / 超时和产物变更；核对结构验证与业务验证分离，受限验证器不能取得未授权访问。

**验收场景**：

1. **SCN-217**：**给定** 维护者扩展了执行前已声明的检查，**当** 正确产物、明确错误产物和缺少可用检查分别到达，**则** 形成 pass / fail / unknown，保存逐项规则、版本和依据；不能把 schema 或文件存在检查冒充未检查的业务语义。
2. **SCN-218**：**给定** checker 超时、不可用或返回不可解释结果，**当** 归并，**则** 未有已知失败时为 unknown；已有必需项明确失败仍 fail。验证有界结束并报告具体原因，不自动调用 LLM judge 补 pass。
3. **SCN-219**：**给定** 产物已验证后内容改变，**当** 查询或交付新内容，**则** 旧结论仍绑定旧版本，新版本需重新检查；新版本出现明确错误后为 fail，不能继承旧 pass。未知来源变化同时影响观测 / one-shot 可信度。
4. **SCN-220**：**给定** 候选修改 skill、评分器或保留集，**当** 评估，**则** 仅允许候选修改授权代码 / 资源，不能改写评分依据自证；格式通过与业务效果分别显示。候选正文未真实执行时不能形成“效果评估通过”。

#### 用户故事 5 - 真实创建、评估、贡献、发布与升级（优先级：P1）

作者在 Codex 创建简单套件，使用者在双端安装与改进，维护者通过公开 GitHub PR 审阅可验证结果，最终确认发布；其他安装使用者显式更新。

**为何此优先级**：验证五项能力能组合成用户要求的真实闭环。

**独立测试**：保留实际 creator、双端 harness、baseline / candidate 运行、GitHub PR / commit / Release URL 与发布包安装结果；本地 bare Git、fake provider、固定 renderer 仅作本地回归证据。正式发布动作等待最后确认，未授权时保留可审阅准备结果并说明尚未发布。

**验收场景**：

1. **SCN-221**：**给定** 合成输入与简单文本 / 报告需求，**当** Codex 真实 creator 创建并封装套件，双端从安装资源正常使用，**则** 每个 skill 有独立入口、套件共享 runtime / 维护资源，实际调用自动进入统计；WorkBuddy 不需预装 Codex 或 SELC 本体。
2. **SCN-222**：**给定** 使用者显式发起改进和隔离候选，**当** 相同实际 harness / 模型条件执行 baseline 与 candidate 正文的固定回归 / 保留集，**则** 独立 checker 输出逐例业务结果、介入、耗时 / 可获得成本与对比，绑定实际版本；不可观测成本标未知，不能用固定 renderer 冒充运行。候选未达预先记录标准、证据不足或预算耗尽时停止发布并保留报告。
3. **SCN-223**：**给定** GitHub 真实账号、公开仓库 URL 和权限已核验，**当** 准备贡献，**则** 创建贡献分支及真实 PR，提供 diff、说明、报告和完整包的可审阅依据。中心更新 / 合并改变实际候选时，重新校验受影响依据；权限不足清楚停止，不默默直推默认分支，也不上传本机业务 / 反馈正文或统计库。
4. **SCN-224**：**给定** 已审阅且可发布的准确版本和完整套件包，**当** 维护者最后确认，**则** 发布新的整套版本并验证 GitHub Release 可读、包可下载 / 安装；未确认时不正式发布。不增加贡献者与维护者双重强制批准；用户有发布权限可兼任维护者。

#### 边界情况

- 宿主原生入口不受支持、未发事件且无可回放依据：支持状态 / gap 如实显示，不承诺不可观测路径零漏记；受管路径采集不可用按 DEC-204 暂停。
- 一次业务动作中途写库失败：保留可证实事实，不假定外部动作未发生，不无条件重新执行；恢复协议由 Plan 明确并验证。
- 未知参与者、混合权限 / 业务决策消息、原要求纠错混合新要求、跨会话无 handoff 证据：相关分类或归属 unknown，不通过持续提问要求用户补记统计。
- 内部草稿 / 自动重试不是首次交付；首次真正交付后即使自动补救成功，首次失败事实仍保留。
- 没有反馈时不把等待变成功；unknown 不能因全体样本未知而从分母移除。导入旧记录同样不补造采集证据。
- 真实远端权限尚未核验、用户桌面操作尚未发生、provider 不可用、请求预算用尽或发布未最终确认：保留已完成本地证据，准确列出未验收步骤，不以绕过限制补齐。

#### 有限接入探针（2026-10-20）

- **目标**：证明真实宿主调用能自动落入 SQLite，并检验仅查看 skill 不计业务调用、当前调用缺少采集证据时受管入口停止。它不验收完整 one-shot 分类器、所有调用路径或业务验证器框架。
- **方法**：用隔离的简单 skill 生成固定文本产物；宿主原生 hook 自动接收事件，受管业务入口自动登记启动与产物摘要。使用者和业务 Agent 无需执行 `task` / `call` / `delivery` 记录命令。模拟事件只检验探针程序，另标 synthetic，不能作为真实接入证明。
- **边界**：每端最多 3 个小场景，串行执行；使用本地合成输入、不写真实远端。每次启动前核对当前路径与模型，保留事件原件和执行证据；失败停止对应实验，不通过危险参数绕过信任或沙箱。后续批量模型评估不在此预算。

- **已观察限制**：当前 Computer Use 工具明确禁止操作 `com.openai.codex`；不能绕过该限制。先使用独立 Codex CLI 验证原生接入，保留“桌面未验证”；WorkBuddy 用桌面实际路径。原生 hook 的必要信任按宿主要求完成，配置须可审阅。
