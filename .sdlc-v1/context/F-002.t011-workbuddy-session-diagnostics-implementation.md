# F-002 / T011 WorkBuddy session diagnostics implementation evidence

## Scope

This untagged T011 source increment adds a diagnostic-only parser for the observed WorkBuddy 5.9.2 native session JSONL serializer. It does not start WorkBuddy or a model, alter account configuration, write a policy sidecar, change qualification consumers, or make a WorkBuddy result eligible.

The parser reads only the existing `session/native-evidence.json` locator and its original native `.codebuddy` or `.workbuddy` project-session file. It validates the attempt ID, bounded cutoff, SHA-256, canonical path hash, device, inode, regular-file identity, exact native project/session path, UTF-8 JSONL records, frozen request prompt, explicit scope, unique record/call/result IDs, model identity, and parent chain. Its output has `schema_version: 1` and `parser: workbuddy-session-diagnostics-v1`.

The bounded 5.9.2 shape may have multiple reasoning, assistant, and tool steps for one request. The parser aggregates a single consistent actual model and request model ID/name across those current-request steps. It accepts only these observed parent relations:

- same-step `reasoning` or completed assistant to a call; and
- a completed, indexed prior result to a next assistant or call with a different message ID and strictly larger step.

A `function_call` may omit `status`; its paired `function_call_result` must have `status: completed`, exactly reference the call, and have a dictionary or list output. The parser builds one call/result index, so a duplicate, missing, or unlinked call/result record remains unavailable. Calls and results from another `conversationRequestId` are excluded from current-request tools.

Only the nested `session-meta.meta["codebuddy.ai/hostKind"]` string is read for `host_kind`; top-level host or version fields are ignored. Matrix `host_version` is reported as `matrix.host_version`, while surface remains unavailable. Malformed or conflicting nested metadata, missing or duplicate call/result IDs, incomplete results, model conflicts, broken parent chains, result-transition step reversal, and wrong-request transitions remain unavailable.

The accepted facts are diagnostic only: actual model, request model ID/name, session/request IDs, nested host kind when present, and completed current-request tool names with `function_call` / `current-request` source and scope. `permission_mode` and `initial_tool_names` are always null. The diagnostic is always `qualification_support: unverified` with `workbuddy-effective-policy-unavailable`; it contains neither raw prompt, command, output, token data, policy body, raw session path, nor a tools-policy hash.

`_reconstruct_attempt` attaches this object only for the existing WorkBuddy unverified path and preserves its legacy outer `unknown` reason. `_read_attempt_native_context` remains qualification-only and returns no WorkBuddy context. The four shared qualification consumers are unchanged.
