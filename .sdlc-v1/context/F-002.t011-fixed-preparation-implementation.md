## Implemented behavior

- New policy templates are schema 2. Their fixed CLI profile adds the one
  literal non-business preparation instruction, and `preparation_guidance`
  separately binds its role, fragment kind, digest, and summary.
- The normalizer and argv renderer explicitly dispatch schema 1 and schema 2.
  Schema 1 retains its original object shape, profile, and argument order.
- Schema 2 adds the literal to the bound final argv. The policy binding and its
  configuration hash include the independent guidance summary; the durable
  launch claim binds the resulting argv.
- Native reconstruction accepts the official generic kind only when exactly
  one matching-turn developer-vector item has the fixed full literal before
  the matching user request. It rejects a duplicate, another turn, a late
  injection, a changed literal, an unknown mixed kind, or unequal content/kind
  vectors. A successful reconstruction publishes the independent summary, not
  as a tools-policy field.
- The two managed-runtime initialization readers recognize the official kind.
  The evaluator remains responsible for exact literal validation, so that core
  parser recognition does not promote arbitrary generic text.
- README, author instructions, and generated `MAINTENANCE.md` call this
  unreleased T011 source behavior schema 2 and retain WorkBuddy diagnostics as
  unverified because effective policy evidence is absent.

The fixed literal allows only an absolute host-metadata routing read with one
`/bin/cat` command. It runs that routing entry's literal managed `invoke`
exactly once, then uses the immutable business body returned by `invoke` only
when it declares a fixed-script managed action with `--request-source native`.
It allows no scratch request or early input read, one independent publish, and
stops on the first error or successful publish. It has no business skill name,
input, answer, oracle, or holdout.
